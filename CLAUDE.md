## Companion

The desktop app lives in `companion/` (Rust workspace + `ui/` React frontend, Tauri v2).

- `make -C companion check`: build, clippy (`-D warnings`), Rust tests, frontend build, lint and tests
- `make -C companion dev`: run the app with hot reload
- `make -C companion dev` and `make -C companion build` keep their own data (`<app data>.dev`,
  keychain entry "Mrglglgl (dev)", window titled "Mrglglgl (dev)"), so trying a change never touches
  the installed app's; they read the same game journals. Only release builds (CI) use the real data
- Builds default to `nice -n 19` and two jobs so a game on the same machine stays responsive;
  `JOBS=0 NICE=` for full speed
- TypeScript bindings in `companion/ui/src/bindings/` are generated by ts-rs (`make -C companion
  bindings` for core types, `make -C companion test` for all); commit them
- Never write under the World of Warcraft folder, with one exception: the addon manager
  (`companion/crates/mrglglgl-core/src/addon_install.rs`) may create, replace or delete
  `<flavor>/Interface/AddOns/Mrglglgl/` and its own working folders
  `<flavor>/Interface/AddOns/Mrglglgl-staging-<id>/`, where `<flavor>` is a discovered WoW: Forever
  flavor folder, and may create `<flavor>/Interface/AddOns/` when `<flavor>/Interface/` exists. It
  writes nowhere else under the game folder (not `WTF/`, no SavedVariables, not `Screenshots/`,
  not another addon's folder) and never while the game runs. Exports, the website, backups and
  every other feature keep the full rule
- Never execute Lua, with one exception: the addon's own tooling may be run from the repository,
  `make -C addon check` (lint and specs), `make -C addon package-check` and `make -C addon fixtures`
  (regenerates `fixtures/savedvariables/`), since that is the only way to verify an addon change
