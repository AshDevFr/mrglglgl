# SavedVariables fixtures

Files in the exact format the WoW: Forever client writes, used by the addon's specs and by the
app's parser and schema tests, so both sides are tested against the same data. The field reference
is `../docs/schema.md`.

| File | What it covers | How it is made |
|---|---|---|
| `savedvariables/real-session.lua` | A short real session: login, zone, discoveries, logout | Captured from a live Forever client, then the character name, surname and realm replaced with fictional ones. Not regenerated |
| `savedvariables/synthetic-character.lua` | Four days: a compacted day (digest only), a day with every event kind (quests, kills with an elite, a murloc and a withheld target, a boss, deaths by drowning and by murloc, fishing with a boot, loot, a companion, a level-up screenshot), a day of only fishing, a day where nothing happened | Generated by `addon/tools/fixtures.lua`, which plays those days through the addon's own code |
| `savedvariables/synthetic-account.lua` | Account-wide settings after those sessions (7-day retention, level-up screenshots on) | Generated, as above |
| `savedvariables/unknown-fields.lua` | The synthetic journal plus fields a newer addon might add (top level, day, event) | Generated, as above |
| `savedvariables/schema-0.lua` | A journal at schema 0, to exercise migration and the app's handling of old schemas | Generated, as above |

Regenerate after changing the addon with `make -C addon fixtures`. The addon's specs fail while a
generated fixture is out of date. Generation runs in UTC so timestamps and day keys are identical
on every machine.

Only fictional names may appear in these files: they are public.
